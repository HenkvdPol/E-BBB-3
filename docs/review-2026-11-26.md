# Independent review of the framework study — 26 November 2026

## Conclusion and scope

Reviewed PR #6 at `a8a915f6bdbe6115f388a718651489973d38e19e`, against the request to simplify the code and study
`framework.tex` first. The new architecture does meet that scope: one e-process, three borrowing engines and a
scaled-Beta representation benchmark. The active computational modules are about 570 lines including comments,
plus the 113-line driver; the 136-line reference file is for validation. The two-way sampler still contains dense
numerical code, so shorter code should not be equated with trivial code.

The earlier executable R files and checks are byte-identical to the PR base after relocation to `legacy/`.
Design-optimal comparators, Bayesian decisions, Simon and flexible inclusion are not invoked by the new study.
The runner sources the reference functions but does not run JAGS/quadrature during the trial study.

A substantive batching defect was found and corrected. The original PR head must not be used for production
simulation. The corrected implementation is a suitable basis for the next focused validation step; a complete
operating-characteristic study has not been run.

## 1. Initial-prior replication: corrected

Original `R/simulate.R` reshaped the K-by-G initial prior matrix into an (S K)-by-G matrix using `matrix()`
before repeating its rows. R recycles matrix entries columnwise, so this moved weights to different support
points instead of copying the prior for each simulated trial. The engine's normalization check occurred before
that transformation.

An independent Python calculation using R's column-major recycling and the actual no-borrowing defaults
(p0 = 0.1, pbar = 0.2, theta width 0.05, 164 restricted support points) gives:

| Trials per worker | Sum of used weights | Sum of weight times support point |
|---:|---:|---:|
| Correct prior | 1 | 0.4959685404 |
| 1 (original code) | 1 | 0.4959685404 |
| 2 (original code) | 1.0059693852 | 0.6173322993 |
| 125 (original code) | 1 | 0.7108697144 |
| 500 (original code) | 1.0178653212 | 0.7077171463 |

For rows that do not sum to one, the last column is a weighted sum, not a probability-distribution mean.
Under independent Bernoulli(p0) outcomes, the expected first-block factor equals the sum of the supplied
weights. Values greater than one break the assumption needed by the e-process proof. Even when the sum
accidentally remains one, the intended prior is still wrong.

The fix copies the K-by-G prior **rows directly**, then checks the assembled weights. Three regressions use
distinct basket priors and fixed outcomes to verify:

1. First-block factors agree with independent direct mixture calculations.
2. Every trial uses the correct basket-specific prior mean.
3. Batched trials agree with separate one-trial runs for a deterministic engine.

The reported N_SIM=2 smoke run on two cores gave one trial per worker and therefore did not expose this defect.
The engine-level exact-path tests bypass `simulate_trials()`, so they could not detect it either.

Correction commit:
[`d0b8d5b`](https://github.com/HenkvdPol/E-BBB-3/commit/d0b8d5bb4a085bd7e84dfa7b727029ca1a604af6).

## 3. What “exact” and “matched priors” mean

The finite block-factor sum is evaluated directly from the weights supplied to the e-process. These weights
are approximate posterior calculations: one-way quadrature; finite MCMC, numerical grids, interpolation,
clamping and Rao–Blackwell reconstruction for the two-way engine. Empty-platform integration is deterministic
quadrature, not an exact continuous integral.

Numerical posterior error can affect power and borrowing. It does not invalidate a prior that actually satisfies
support, normalization and predictability. The batching defect was important precisely because it could break
normalization after the engine check.

HN(1/sqrt(3)) for three SDs matches the **untruncated expected total EX variance** to one-way HN(1), not the full
prior law. In the continuous idealization, the total variances follow chi-square(3)/3 and chi-square(1),
respectively. The actual finite grids give expectations approximately 0.999713 and 0.998935. This tiny mismatch
is not a blocker, but “identical priors” would be misleading.

The saved reference comparisons are useful evidence, not a proof that finite MCMC is unbiased. Shared
likelihood tables also mean that the quadrature comparison does not independently establish grid convergence.
JAGS uses continuous parameters and has its own Monte Carlo error. The documentation now states these limits.

## 5. Study details and remaining work

The driver specifies 10 scenarios, two recruitment designs and four prior choices (80 cells), p0 = 0.10,
p1 = 0.30, alpha = 0.05 and 30 patients per basket. Unbalanced rates are 0.5 and 1; cell (3,3) is absent and
basket (2,3) enters at time 20. Entry is aligned with global analyses every five time units. Arbitrary entry
events and outcome delays are not implemented by this scenario.

Keep the scientific scope fixed. Before production:

- Separate outcome and fitting RNG streams. Data seeds are `base + chunk`; fitting adds the analysis index,
  so chunk 1's first fit can reuse chunk 2's outcome seed. This creates avoidable cross-replication dependence;
  it does not itself establish a violation of the per-basket theorem. Validate paired comparisons and the
  assumptions behind ordinary Monte Carlo standard errors.
- Check grid resolution and MCMC draws for selected sparse/heterogeneous states. The saved comparisons show
  useful accuracy, but some early-state block factors differ by roughly 12–15%.
- Choose operating-characteristic precision explicitly. For independent replications, N_SIM=1000 gives an
  approximate standard error of 0.0069 for a true rate of 0.05.
- Conduct a small timing/pilot run only after approval, as already agreed in decision D9.

The three-CPU-hour claim is a throughput extrapolation:
10 x (6 + 16) x 1000 x (0.035 + 2 x 0.007) seconds is about 2.99 hours. It omits fixed per-fit,
setup, process and plotting overhead; early stopping and repeated states can reduce cost. It is not an upper
bound. The checked-in validation CSV has no timing column, so the quoted throughput remains the author's
benchmark rather than a timing result independently recomputed from that CSV.

Empirical posterior coverage is a diagnostic, not guaranteed frequentist coverage. A dedicated false-borrowing
statistic remains unimplemented. Hyperprior sensitivity is pending. Partial exchangeability, entry-event
redesign, drift/delay/allocation extensions and the old comparator families remain later work.

No pilot or full operating-characteristic simulation was run for this review.
